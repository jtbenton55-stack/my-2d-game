## Implementation summary

### Combined Mission Dock plugin
- Script-built `@tool` dock in `MissionDock.gd` with `TabContainer` tabs:
  - **Mission Authoring Palette**
  - **Mission Assist Browser**
- Plugin follows patterns from PVGames Object Palette / Scene Asset Browser / Mission Paint Dock.
- Canvas input forwarding enabled; mouse placement arms/disarms with Esc/RMB; release consumption prevents editor selection leak.

### Mission Authoring Palette
- Supports all approved mechanic classes: SearchZone, RewardNode, LockedInteractionNode, RouteUnlockNode, InteractiveContainer, ExtractionZone, SideObjectiveNode, TriggerZone.
- Safe defaults applied per mechanic type (flags, prompts, one-shot, interaction mode).
- Parent resolution: explicit path from **Use Selected Node As Parent**, existing `MissionMechanics`, or `MissionMechanics` created inside the same placement UndoRedo action when missing. Blank `Parent Target Path` never uses editor selection implicitly.
- Refuses unsafe parent targets (generated runtime collision layers, Phase0J/Phase0K fragments in path).
- Optional in-memory starter RequirementSet / success EffectSet (no `.tres` files).
- Dry Run Placement is non-mutating (`_preview_placement()` never mutates the scene).
- Place At Typed Position / Place With Mouse use `EditorUndoRedoManager` with owner setup and selection cleanup on undo (`_undo_remove_placed_mechanic` / `_undo_remove_placed_mechanic_with_parent`).
- SideObjectiveNode refuses placement without explicit objective_id.

### Mission Assist Browser
- Read-only `_refresh_scene_audit()` scans edited scene recursively for supported mechanic scripts.
- Checks duplicate mechanic_id and duplicate flag fields, missing required IDs, broken NodePaths (local + scene-root resolution), collision shape validity, requirement fact types, effect key/target requirements, extraction warnings.
- Filters by severity/issue type; Select Node / copy helpers.

## What was intentionally not implemented
- Auto-fix of audit issues
- External `.tres` RequirementSet/EffectSet file authoring
- MissionManager, sequence tooling, inventory/heist kit, card modifiers, stealth/AI/NPC systems
- Mechanic gizmos (deferred)
- Batch placement / brush modes

## Pre-QA fix pass (2026-06-13)

Read-only review found three blockers; all fixed before manual QA:

1. **`_preview_placement()` missing `parent`** — `_commit_placement()` cast `preview["parent"]` but preview only returned `parent_path`. Preview now returns `parent`, `needs_mission_mechanics`, and related fields from non-mutating `_resolve_parent()`.
2. **MissionMechanics created outside UndoRedo** — `_resolve_parent(create_if_missing=true)` called `scene_root.add_child()` directly. `_resolve_parent()` is now read-only; placement creates `MissionMechanics` + mechanic in one UndoRedo action via `_undo_remove_placed_mechanic_with_parent()` when needed. Explicit **Ensure MissionMechanics Parent** still uses its own UndoRedo action.
3. **`project.godot` contradiction** — repo already enables `res://addons/mission_dock/plugin.cfg`. Docs/report/plan updated to match (plugin auto-loads for QA); no unrelated `project.godot` edits.

Post-fix validation: `git diff --check` PASS; Phase 2K static validator PASS.

## Post-manual QA fix pass (2026-06-13)

Jake manual QA found four issues; all addressed in this pass:

1. **Unsafe implicit parent from editor selection** — `_resolve_parent()` no longer uses the currently selected `Node2D`. Blank `Parent Target Path` resolves to existing `MissionMechanics` or `needs_mission_mechanics=true`. Explicit path only via **Use Selected Node As Parent**. Placement no longer auto-fills `Parent Target Path` after creating `MissionMechanics`, so subsequent placements with a blank path still target `MissionMechanics` even when a placed mechanic remains selected.
2. **Assist Browser literal BBCode** — `_audit_details.bbcode_enabled = true` (and template details panel too) so `[b]Error[/b]` renders correctly.
3. **Starter Requirement empty array** — `_build_starter_requirement()` now builds `Array[MissionRequirement]` via typed `append()`, sets `resource_name` on resources, and uses `expected_value_type = "exists"` for EXISTS/NOT_EXISTS operators (matching test patterns).
4. **Requirement/effect hard to verify** — added **Last Placement Summary** panel in Authoring Palette; dry run and placement populate mechanic/parent/requirement/effect fields. Assist Browser issue details now append read-only RequirementSet/EffectSet summaries when the issue node is a supported mechanic.

Unrelated files **not touched**: Parmida JSON churn, staged `GdUnitRunner.cfg`, staged `reports/report_1/`.

Post-fix validation: `git diff --check` PASS; Phase 2K static validator PASS; Godot LSP on `MissionDock.gd` PASS.
